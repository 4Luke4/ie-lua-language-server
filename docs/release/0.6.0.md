# 0.6.0 stable release record

## Objective and compatibility

Deliver dependable everyday Lua 5.2, LuaJIT, and Infinity Engine `.menu` editing through the
existing VS Code extension and bundled stdio server. Preserve setting keys/defaults, command IDs,
language IDs, VS Code 1.100 compatibility, Node 24 tooling/stdio support, IPC integration, legacy
API manifests, and six source sections. Within 0.6.x, intentional correctness fixes are documented;
no intentional breaking changes to these documented interfaces are planned.

Workspace operations cover open documents, rename remains within one document, and formatting
only removes safe trailing whitespace. Closed-file indexing, cross-file rename, deeper type
inference, external formatting, new dialects, and Marketplace automation are deferred.

## Acceptance requirements

| Area               | Required result                                                                                                                                                  |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Document lifecycle | Stale configuration or analysis cannot cross versions, sessions, configuration/API generations, close, or shutdown. Diagnostics identify their analyzed version. |
| Formatting         | Exact safe deletions; string/comment contents, line endings, and final-newline state are preserved. Menu files remain unchanged.                                 |
| API recovery       | Invalid candidates are rejected before installation. Empty startup degrades visibly; failed reload retains prior data; restored data reloads successfully.       |
| Commands           | Untitled validation works, unsupported-editor validation is a no-op, and reload success is reported only after replacement.                                      |
| Responsiveness     | Every fixed workload passes correctness, report-completeness, timeout, and clean-shutdown checks; raw and aggregate timings are retained.                        |
| Distribution       | Both VSIX channels pass archive and installed-extension tests across the existing OS/editor/accessibility matrix.                                                |
| Release gates      | Final-head Verify, CodeQL, dependency review, commit policy, pinned regeneration, and stable release dry-run pass.                                               |

## Evidence and publication handoff

The PR is the evidence record: attach the final tested SHA, exact Actions run links, downloadable
VSIX and report artifacts, responsiveness results, and all missing or intentionally skipped coverage.
Do not describe this release as verified until the required jobs pass. The `Unreleased` changelog
heading denotes preparation, not publication; the existing 0.5.3 preparation date is preserved.

Run Release on the final branch revision with `release_type=stable`, `tag_name=v0.6.0`, and
`dry_run=true`. After review and merge, publication is a separate maintainer action using the
merged default-branch commit and the existing Release workflow. Publish only that workflow's
audited artifact. Never overwrite an existing tag or release. Marketplace publication remains a
separate maintainer operation.

Review failures before rerunning Actions. Obtain formatting, lockfile, and generated-data patches
through the existing maintenance workflows. No installation, testing, building, generation,
formatting, or packaging runs locally.

## Coverage limits

No Kate GUI automation, screen-reader usability certification, additional CPU architectures beyond
the runner matrix, or arbitrary-project performance guarantees are claimed. Responsiveness evidence
covers synthetic Linux stdio workloads and does not certify bounded memory use. Lua fixtures and
upstream documentation are parsed as data, never executed. Runtime dependencies and generated API
content are unchanged by this milestone; their existing notices remain applicable. Security support
continues to cover only the latest released version.
